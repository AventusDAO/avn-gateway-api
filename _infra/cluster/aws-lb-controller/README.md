## AWS loadbalancer controller
Controls the creation of AWS load balancers to forward traffic to our ingress controller. The avn gateway uses the [NginX Ingress](https://kubernetes.github.io/ingress-nginx/) for managing our ingress traffic, it handles SSL termination and path routing. The rules are interpreted from kubernetes Ingress manifests with the nginx annotation `kubernetes.io/ingress.class: nginx`.

the Loadbalancer controller must have permission to create/modify loadbalancers, the iam permissions are defined [here](https://github.com/Aventus-Network-Services/avn-gateway-api/blob/main/_infra/terraform/modules/k8s-service-account-permissions/lb-controller-policy.tf). We create a Kubernetes Service Account that is directly linked to an IAM role. The controller assumes this role via the kubernetes service account granting it all the necessary permissions.

The IAM role must provide a specific namespace and serviceaccount name for the principal oidc provider (created for the cluster by the eks terraform module). An example can be found [here](https://github.com/Aventus-Network-Services/avn-gateway-api/blob/41900504d0c0fd9e2b805ce770d6930081fc229a/_infra/terraform/modules/k8s-service-account-permissions/lb-controller-policy.tf#L242), notice that the IAM role can only be assumed by a kubernetes service account in the `kube-system` namespace with the name defined by the `lb_controller` local variable. We tell the helm chart to use this pregenerated service account in the [values.yaml](./values.yaml)

Our Nginx Ingress controller has a service type of `LoadBalancer` that instructs the lb controller to create a network loadbalancer to route traffic to the nginx service. Any service within our cluster can change their type to LoadBalancer and it will have the same effect - Create an AWS loadbalancer to route traffic directly to its kubefrnetes service.
